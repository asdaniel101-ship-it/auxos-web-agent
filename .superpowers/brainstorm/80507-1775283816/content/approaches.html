Smart Popup Agent — Approach Comparison

How should we architect the idle-detection + peek-in experience?

A

Client-Side Idle Watcher

How it works: A React hook (useIdleDetection) tracks mouse movement, clicks, scrolls, and keystrokes per page. After a configurable idle threshold (e.g., 30s), it triggers the peek animation. The hook is page-aware — it knows which CRM page you're on and passes that context to the agent's opening message.

Peek behavior: The agent character slides in from the right edge of the screen with a soft ambient glow radiating behind it. A small speech bubble shows a contextual message like "Stuck on contacts? I can help you find someone." Clicking it opens the existing chat panel with that message pre-loaded.

Pros

  • Simple — no new APIs, all client-side
  • Fast to ship — hooks into existing agent infra
  • Easy to tune thresholds per page

Cons

  • Limited "intelligence" — just a timer, doesn't truly understand user intent
  • Could feel random if thresholds aren't well-tuned

Recommended — simplest path to the full experience

B

LLM-Powered Context Evaluator

How it works: Same idle detection as A, but when idle is detected, we send a lightweight LLM call with context (current page, visible data summary, recent navigation history) to decide whether to pop up and what to say. The LLM generates the peek message dynamically.

Peek behavior: Same peek-in animation and glow, but the message is AI-generated and highly contextual. Instead of "Need help with contacts?" it might say "I see you have 3 contacts without email addresses — want me to help fill those in?"

Pros

  • Genuinely intelligent — messages feel personal and relevant
  • Can analyze the actual data on screen
  • Differentiating — no one else does this

Cons

  • API cost on every idle trigger (needs throttling)
  • Latency — 1-3s delay before peek appears while LLM responds
  • More complex to build and test
C

Hybrid: Client Rules + LLM Fallback

How it works: A rules engine maps each CRM page to pre-written contextual messages (e.g., on Deals page → "Want me to update any deal stages?"). These fire instantly on idle with no API call. For pages without specific rules, or after the user dismisses a canned message, fall back to an LLM call for a smarter suggestion.

Peek behavior: Same visual treatment. First peek is instant (pre-written). If dismissed and user stays idle again, the second peek is LLM-powered and more specific.

Pros

  • Best of both worlds — instant first peek, smart follow-up
  • Low cost — most interactions never hit the API
  • Progressive sophistication

Cons

  • Most complex to build — two systems to maintain
  • Pre-written messages need ongoing curation
  • Overkill for a first version
